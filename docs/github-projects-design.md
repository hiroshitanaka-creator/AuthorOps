# GitHub Projects 設計案 - AuthorOps

## 目的

執筆・論文の進损を視覚的に管理し、「何をすべきか」を一目で理解できる状態を作る。

GitHub Projectsを使うことで、Issueと連動しながらカンバン風に進损を管理できる。

---

## 推奨ビュー構成（Projects v2）

### メインビュー：「執筆進损カンバン」

| ステータス | 説明 | 使うレーベル主に |
|-------------|----------|-------------------------|
| 未着手 | アイデアが出たが、まだ動き出していない | `idea` |
| アイデア検討中 | アイデアをもう少し考えている階段 | `idea` |
| 構成考案中 | 章の構成を考えている | `chapter-draft` |
| 執筆中 | 実際に文章を書いている | `chapter-draft` |
| 推敷中 / セルフPR中 | 自分でPRを作って推敷中 | `chapter-draft` |
| 校正中 | textlint・人間校正を行っている | `chapter-draft` |
| 完了 | 章が完成した | - |

### オプションビュー

- **アイデア集結ボード**: `idea` レーベルのみを集めて表示
- **章別進损**: 各章のIssueをグループ化して表示

---

## 推奨レーベル一覧

| レーベル | 色 | 使う場面 | 説明 |
|-------------|-----|------------------|----------|
| `idea` | 青 | アイデア階段 | 章になる前の生のアイデア |
| `chapter-draft` | 緑 | 執筆中 | 実際に章を書く用のIssue |
| `needs-research` | 黄 | 調査中 | 参考文献・調査が必要 |
| `blocked` | 赤 | ブロック中 | 何かの理由で進めない |
| `reference` | パープル | 参考情報 | 参考文献・引用候補用 |

## カスタムフィールド（Projects v2）

| フィールド名 | タイプ | 使い方 | 例 |
|------------------|-------------|-------------|------|
| 優先度 | Single select | 高・中・低 | 高 |
| 推定執筆時間 | Number | 時間（分） | 120 |
| 進损率 | Number | 0〜100 | 65 |
| 関連章 | Text | 章番号 | 第3章 |

---

## 設置手順（実際に作るとき）

1. GitHub上で「Projects」→ 「New project」をクリック
2. **Table** または **Board** を選択（初心者はBoardが分かりやすい）
3. 上記のステータスを列として設定
4. レーベルを作成してIssueに設定可能にする
5. Custom fieldsを追加
6. フィルター・ソートを保存してビューとして保存

---

## 優先度付けの思考

- 最初は簡単に「未着手 / 執筆中 / 校正中 / 完了」の4段階で始めるのがおすすめ
- 習慣がついたら、「アイデア検討中」や「推敷中」を追加
- Projectsは「観える化」が主目的なので、変に複雑にしすぎないことが大切
